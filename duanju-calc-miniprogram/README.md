# 短剧分账计算器 · 微信小程序

给做短剧的人做工具：**分账计算器 + 平台政策情报站**。
输入播放量、平台、分成比例、成本，自动算出分账收入、回本线、利润；聚合红果、抖音、快手、爱奇艺、腾讯视频、优酷、微信绿泡泡的最新分账政策。

- 技术栈：微信小程序原生（无构建步骤）+ 云开发（可选）
- 数据基准：2026-10-13
- 商业化：基础计算免费；阶梯激励精确模型 + 政策变动提醒 ¥9.9/月 或 ¥99/年

## 二、快速开始（3 步跑起来）

1. **导入项目**：微信开发者工具 → 导入 → 选择本目录 `duanju-calc-miniprogram/`
2. **AppID**：没有正式 AppID 时选「测试号 / 游客模式」即可编译预览（`project.config.json` 已填 `touristappid`）；有 AppID 后替换 `project.config.json` 中的 `appid` 字段
3. **编译**：点「编译」即可在模拟器看到三个 Tab，计算器全部功能可交互

> 当前会员支付为**模拟流程**（弹窗确认后直接开通），正式支付接入见第五节。

## 三、核心计算模型

```
有效播放量   = 总播放量 × 有效播放率
基础分账     = 有效播放量 ÷ 1000 × 千次单价 × 分成比例
分账总收入   = 基础分账 + 阶梯激励加成
利润         = 分账总收入 −（制作 + 投流 + 人力 + 算力AI）
回本线(播放) = 总成本 ÷（千次单价 × 分成比例 × 有效播放率 ÷ 1000）
```

千次单价按平台模式区分：IAA 平台 = eCPM；IAP 平台（抖音）= 1000 × 付费率 × 客单价；会员分账平台 = 分账单价（估算值，可调）。

平台参数（单价、分成区间、阶梯激励规则）集中在 `utils/data.js` 的 `PLATFORMS`，全部带公开来源与生效日期。

## 四、政策数据更新流程（产品的真正护城河）

**方式 A：改文件发版**（适合早期，日更以下频率）
编辑 `utils/data.js` 中的 `POLICIES`，同步更新 `META.version`，提审发版。

**方式 B：云数据库热更新**（推荐，政策变化快时不依赖发版）
1. 开通云开发，建 `policies` 集合，字段对齐 `POLICIES`（`id / plat / cat / date / impact / title / sum / src / sort`）
2. 部署 `cloudfunctions/getPolicies`（右键上传并部署，云端安装依赖）
3. 客户端改造（约 20 行）：`pages/news/news.js` 的 `filterNews()` 前先 `wx.cloud.callFunction({ name: 'getPolicies' })` 拉取，失败回退到本地 `POLICIES`
4. 更新节奏：每周一固定发版；重大活动（如绿泡泡 Q4 激励）48 小时内跟进；每次更新后对订阅用户发一次订阅消息

### 5.2 云开发部署步骤（约 30 分钟）

1. **开通环境**：开发者工具 → 云开发 → 开通，创建环境后把环境 ID 填入 `utils/cloud.js` 的 `ENV_ID`
2. **创建数据库集合**：云开发控制台 → 数据库 → 新建 `entitlements`、`subscriptions`、`policies` 三个集合
3. **部署云函数**：对 `cloudfunctions/` 下 4 个函数逐个右键「上传并部署（云端安装依赖）」
4. **订阅消息模板**：公众平台 → 订阅消息 → 申请「政策更新提醒」模板，把模板 ID 替换到 `pages/news/news.js`（`YOUR_SUBSCRIBE_TEMPLATE_ID`）与 `cloudfunctions/sendPolicyNotify/index.js`
5. **推送政策更新**：更新政策后，云函数控制台 → sendPolicyNotify → 测试，传入 `{"title":"...","summary":"...","date":"..."}`，已订阅用户收到微信提醒（一次性订阅：用户需重新订阅才能收下一次）
6. **权益同步**：支付成功后客户端调 `entitlement` 写云端；每次打开会员页自动同步，过期自动失效，无需人工干预

### 5.3 正式支付接入

`pages/profile/profile.js` 的 `onBuyTap` 中，将模拟逻辑替换为：

```js
wx.requestVirtualPayment({
  offerId: '你的 OfferID',     // 虚拟支付后台获取
  buyQuantity: 1,
  env: 0,                     // 0 正式环境 1 沙箱
  currencyType: 'CNY',
  platform: 'android',
  success: (res) => {
    // 支付成功 → 写云端权益，orderId 传虚拟支付订单号
    cloud.callFunction('entitlement', { action: 'set', plan: this.data.plan, orderId: res.orderId || '' })
    store.setPro(true)
  }
})
```

> iOS 端需配置小程序「简称」并满足 Apple 支付要求（微信 8.0.68+、中国大陆 App Store 账户）；`offerId` / `AppKey` 在虚拟支付开通后获取。正式环境建议增加订单核验（虚拟支付订单查询 API）防刷。

**费率与限额（个人主体，2026-10 官方口径）**
- 限额：全终端月支付限额 **10 万元**（各终端合计，非各端分别）
- Android 等端：技术服务费 **1%**，**T+3** 结算
- iOS：走 Apple 支付，佣金 **12%**，约 **45-60 天** 结算（两端均可直接在小程序内购买，无需 H5）
- 退款：支付 180 天内退款退还手续费

**双变现通道设计**
1. **虚拟支付（主）**：月卡 ¥9.9 / 年卡 ¥99 道具直购。个人主体自动续费（连续包月）以官方文档为准，不作为唯一路径，产品上以「月卡/年卡一次性购买」为主

**合规红线**：虚拟商品不得引导至 App / 公众号 / H5 / 个人号 / 网站完成支付；混合型服务（虚拟+实物）需拆分为两笔交易。
